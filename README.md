# QuotaMenu

macOS のメニューバーから AI コーディングサービスの使用枠を確認するアプリです。macOS 14以降のApple Silicon Macに対応しています。

メニューバーは既定でアイコン1個の省スペース表示です。クリックすると全サービスの残量を確認でき、「設定 → 一般 → 省スペース表示」をオフにするとサービス別リングと使用率を表示します。アイコンが他の項目に押し出された場合は、起動済みのQuotaMenuをFinderやSpotlightから開き直すと使用量ウィンドウが開きます。

## 1.1.0の機能

- Claude Code / Codex / Cursor / GitHub Copilot / Antigravity の使用量取得。
- 履歴・通知・警告表示を含む全機能が無料。ライセンス登録は不要です。
- 予定作業時間（15〜240分）と直近の消費ペースを比較し、使用枠に余裕があるサービスを提案。
- グローバルショートカットから使用量ウィンドウを表示。設定 → 一般で割当・変更・解除できます（初期状態は未設定）。
- 1サービス・1件の作業セッション。カウントダウン、開始時の推定と観測消費の比較、任意の枠不足通知、90日間のセッション履歴。
- サービス別の取得元・最終取得時刻・前回値の表示。失敗の分離、取得重複防止、429時のバックオフ。
- サービス・アカウント・使用枠を選択する履歴分析。異なる使用枠の使用率を合算しません。
- 日本語／英語、明暗対応の二重リング、ログイン時起動、Sparkle更新。

[最新のDMGをダウンロード](https://github.com/iyuya1808/quotamenu-dist/releases/download/latest/QuotaMenu.dmg)できます。配布物はDeveloper ID署名・Apple公証を行います。

## インストール

[最新のDMG](https://github.com/iyuya1808/quotamenu-dist/releases/download/latest/QuotaMenu.dmg)を開き、QuotaMenu.appをApplicationsフォルダへドラッグしてください。

Homebrewからインストールする場合：

```sh
brew install --cask https://raw.githubusercontent.com/iyuya1808/quotamenu-dist/main/Casks/quotamenu.rb
```

既存ユーザーはアプリの「設定 → サポート」から更新を確認できます。

## 接続方法

| サービス | 認証・取得方法 |
|---|---|
| Claude Code | CLIでログイン済みのKeychain認証を読み取ります。期限切れ時はCLIで再ログインしてください。 |
| Codex | `$CODEX_HOME/auth.json` または `~/.codex/auth.json` を読み取ります。 |
| Cursor | Cursorアプリの認証DBを読み取り専用で利用します。代替として設定 → アカウントで `cursor.com/dashboard` のリクエストのCookieヘッダーを登録でき、Keychainに保存します。 |
| Copilot | `gh auth login --hostname github.com` 後、設定でCopilotを明示的に有効化します。既存のGitHub CLI認証を利用します。一部のトークン・契約では非公開の使用量APIにアクセスできません。 |
| Antigravity | 起動中アプリのローカルAPIを優先。アプリが閉じている場合はログイン済み `agy` 1.1.11以降で使用量を取得します。CLIがPATHにない場合は `ANTIGRAVITY_CLI_PATH` で指定できます。 |

第三者アプリの認証ファイルを書き換えたり、ブラウザのCookieを自動収集したりしません。通知は既定でオフです。Copilot以外は既存認証を自動検出し、設定で取得を無効にできます。

AntigravityのCLI使用量レポートにはアカウント識別情報がないため、その取得元では残量のみを表示し、アカウントを確認できない予測・履歴保存は行いません。アプリのローカルAPIでも識別できない場合は同様です。

## 予測と履歴の読み方

予測には、同一サービス・アカウント・使用枠・取得元で、直近60分のうち最低3回、15分以上の連続した観測が必要です。15分を超える空白、リセット日時変更、使用率低下で観測区間を分けます。同じリセット日時の2秒以内の揺れは許容しますが、実際のリセット時刻をまたぐ差分は計上しません。消費がない場合や古いデータでは持続時間を表示しません。

「余裕あり」は使用枠の推定です。サービスごとのモデル能力や作業完了を保証しません。作業中にリセットされる枠は、リセット後の予算を先取りせず「注意」と表示します。取得失敗時の前回値は予測から除外します。

新しい観測は `~/Library/Application Support/QuotaMenu/usage_observations.json` に90日間保存します。初回の使用率を消費として計上しません。旧 `usage_history.json` は保持し、別の「旧履歴」として分析できます。旧データは予測に使用しません。`pp` は同じ使用枠の使用率の増分で、トークン数や費用ではありません。

## ショートカットと作業セッション

ショートカットはアプリ起動中に使えます。設定 → 一般 → 使用量ウィンドウのショートカットで、CommandまたはControlを含む修飾キー2つ以上と英数字キーを指定してください。物理キー位置で保存します。登録できない組合せはエラーを表示し、既存の割当を保持します。キー記録中は元の登録を一時解除し、キャンセル・失敗時に復元します。入力監視やアクセシビリティ許可を要求する方式は使いません。Finder／Spotlightからの再オープンも引き続き利用できます。

使用量画面の「作業セッション」で対象サービスと予定時間を選び、開始します。同時に1件だけ実行でき、スリープ中も予定終了時刻は進みます。再起動時は保存した状態から復元し、既に予定時刻を過ぎていれば終了扱いにします。開始時に取得データ・アカウント識別がなければタイマーのみ利用でき、比較を行うには取得後に新しいセッションを開始してください。

比較対象は開始後の連続した成功観測で、同じサービス・アカウント・取得元・枠・枠期間に限ります。15分を超える空白は加算せず、リセット・使用率低下・識別条件の変更では比較を止めます。終了時刻をまたぐ差分を遡って計上しません。結果には観測できた時間と消費、同じ観測時間に対する開始時ペースの推定を表示します。同じアカウントを使う別端末や他の作業の利用も含み、この作業だけの消費量とは限りません。

セッションの枠不足通知は既定オフで、従来の残量通知とは別に有効化します。「余裕あり」を確認した後、不足見込みを連続2回の新しい取得で確認した場合に、1セッション1回まで通知します。開始時から不足見込みの場合や、リセット予定・古い値・取得失敗だけでは通知しません。同時に発生した同一サービスの残量通知は1件にまとめます。通知済み状態を保存してからOSへ送信するため、再起動で再送しません。OSで拒否・配信失敗した通知の再送はしません。予測には既存の観測条件が必要で、長い更新間隔では成立しない場合があります。

セッションは `~/Library/Application Support/QuotaMenu/work_sessions.json` に90日間保存します。開始時の基準値・取得時刻・推定、枠別の観測増分、終了時刻、通知済み状態、ハッシュ化アカウント識別子を保存し、トークン・Cookie・API本文は保存しません。「セッション履歴」から完了済みセッションだけを削除でき、既存の使用量履歴には影響しません。
